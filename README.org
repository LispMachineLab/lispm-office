#+title: LispM Office

A LispM Agent plugin that adds a Work view to your conversation. Each live
conversation has a desk; rooms group projects, and an inspector shows what an
agent is doing and what is in its mailbox. LispM UI draws the controls and view
in graphical Emacs and on a text terminal.

* Using it

Enable the plugin, then click =Conversation= or =Work= in the agent's header.
=C-c O= performs the same toggle in the same window. Returning to Conversation
restores the source buffer, draft, point and scroll position; the agent keeps
running throughout. =q= in Work also returns to the conversation.

Work selects the current agent's desk and room. Click a desk or press =RET= to
open its optional Inspector side window with Work, Mailbox and Character tabs.
In Fit mode, the room fills the available buffer area and its desks reflow when
the window changes size. Avatars and text keep their proportions; saved seat
identities stay unchanged. =Help= lists the view's keyboard commands.
Open Chat navigates to the selected conversation. If you select another agent
in a second window while Work is visible, it follows that agent by default; set
=lispm-office-follow-current-agent= to =nil= to keep your desk selection.

The waiting strip and =n= lead to agents that need you. Rooms grow automatically,
with a map overview when there are many agents. Seats survive restarts; only
=Compact Saved Seats…= removes empty reservations.

| Key             | Action                                      |
|-----------------+---------------------------------------------|
| Arrows / C-b/f/p/n | Select a nearby desk                      |
| n / TAB         | Select the next waiting agent               |
| RET             | Inspect the selected conversation           |
| w / m / c       | Work / Mailbox / Character                  |
| o / s           | Open chat / compose a message               |
| a / d           | Approve / deny one pending permission       |
| A               | Preview and approve this agent’s pending calls |
| x               | Confirm stopping this agent and clearing its queue |
| + / - / 0       | Zoom in / out / fit                         |
| h / r           | All rooms / choose a room                   |
| t               | Toggle text view                            |
| g / q           | Refresh / return to the conversation        |

Approve All is limited to one selected agent and its current turn. A change to
the displayed permissions cancels the preview. Terminal agents expose only the
actions supported by their provider; open their chat for questions or approvals.
Leaving Work releases its inspector and subscriptions. Disabling
=lispm-office-plugin-mode= restores conversations and their original headers,
and removes the plugin's local bindings and observers.

* Installing

Requires Emacs 30.1+, LispM Kit 0.2.0+, LispM UI 0.5.0+ and LispM Agent with the
roster API from the merged [[https://github.com/LispMachineLab/lispm-agent/pull/135][PR #135]]. Use a LispM Agent revision that includes
that API; no released version is assumed here.

With the dependencies already on =load-path=, add this checkout:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/lispm-office")
(require 'lispm-office-plugin)
(lispm-office-plugin-mode 1)
#+end_src

You can also install this repository with =package-vc-install= when the dependencies
are available through your package setup, then enable the plugin as above.

Seats are kept in =office-seats.eld= under =lispm-directory=; set
=lispm-office-seat-file= to use another file. Set =lispm-office-animate= to =nil= to
disable animation. Enabling the plugin does not subscribe to the roster until a
Work view opens. The view does not poll agents and stops its timer while hidden
or idle. It initializes its palette through LispM UI's public API.

* Development

With sibling checkouts of LispM Kit and LispM UI:

#+begin_src sh
make test compile LISPM_AGENT=/path/to/agent-with-roster/lisp
#+end_src

=EMACS=, =LISPM_KIT= and =LISPM_UI= select other binaries or checkouts.
Tests pin a known roster API commit rather than assuming a released dependency.
Integration tests use synthetic conversations with the real roster API; network,
model and tool execution are forbidden. Tests cover persistent layout, large
rosters, current-agent following, conversation restoration, input handling, stale
approvals, mailbox reads and observer/timer cleanup.
Compilation treats warnings as errors. [[file:docs/design.md][Design notes]] describe the data contract.

For an optional developer preview, =M-x lispm-office-demo= opens twelve simulated
agents without starting or messaging anything. =C-u M-x lispm-office-demo= asks
for a count from 2 to 1000. The preview needs only Kit and UI, cannot perform agent
actions and does not change saved seats.
